# litestar-org/litestar — DTO nested models of the same type collide on one name, leaking the module path

- **Issue:** https://github.com/litestar-org/litestar/issues/5102 (filed 2026-09-29 by jeongeundev, 0 comments, no competing PR — sibling fresh Litestar bugs #5100/#5072/#5049/#5025/#5051/#5031 all already had reporter PRs; #5102 was the clean one)
- **Sector:** (5) web/other OSS — run 20, 2026-10-04
- **Bug:** When a model has two fields of the same nested type (`author: User`, `editor: User`), the DTO backend generates the nested transfer-model name from the parent model name + type name only (`PostUser` for both). The first model takes the short schema name; the second falls back in `_create_transfer_model_name` to the raw handler id, producing an OpenAPI component name like `__main__.get_postPostUserResponseBody` — module path and un-camelized handler name leaked into the public schema.
- **Proof (red):** the issue's exact MCVE on main f8a06ef (v3.0.0b0) prints `['GetPostPostResponseBody', 'GetPostPostUserResponseBody', '__main__.get_postPostUserResponseBody']`.
- **Fix:** thread the field name through transfer-type creation (`name_hint`, propagated unchanged through collection/mapping/tuple/union handlers) and use it as the first disambiguation step in `_create_transfer_model_name`, before the existing long-name fallback. Names are unchanged unless a collision actually occurs; on collision the field name is appended (the reporter's own suggested direction). The root-model / cross-handler long-name fallback (covered by `test_dto_openapi_without_unique_handler_names`) is untouched.
- **Proof (green):** MCVE now yields `GetPostPostUserEditorResponseBody` for the second field, no dotted name. Extended shapes verified end-to-end via TestClient: three same-type fields (`PostUser`/`PostUserEditor`/`PostUserReviewer`), two `list[User]` fields, a `dict[str, User]` field, and request+response DTO round-trips — all names unique, all payloads correct. New regression test `test_dto_openapi_same_type_fields_get_field_scoped_names` (both DTO backends) fails on unpatched source, passes patched; full `tests/unit/test_dto/` 265 passed; `tests/unit/test_openapi/` 283 passed, 1 xfailed; ruff clean. One existing test double (`fx_backend` in test_base_dto.py) updated for the new internal kwarg.
