# Electrum — `closeEvent` crashes on a window closed before `__init__` finishes (#10969)

- **Project / repo:** https://github.com/spesmilo/electrum (Bitcoin wallet, Python/PyQt6, active)
- **Issue / bounty:** https://github.com/spesmilo/electrum/issues/10969 — production crash reported via Electrum's automatic crash reporter (crashhub #40555, Electrum 4.8.2, Windows). No bounty posted — fix offered freely, tips welcome.
- **Found:** 2026-10-04
- **Severity / type:** robustness — closing the main window while it is still being constructed raises `AttributeError` instead of closing.
- **Bug:** `ElectrumWindow.closeEvent()` unconditionally iterates `self.closing_warning_callbacks` via `_show_closing_warnings()`, but the list was only created near the **end** of `__init__` — after the status bar, all tabs, the menubar, the Ctrl+W/Ctrl+Q close shortcuts, and `showMaximized()`. The window is already visible and closable before the attribute exists, so a close delivered during construction crashes: `AttributeError: 'ElectrumWindow' object has no attribute 'closing_warning_callbacks'` (exact production traceback: `closeEvent` line 2816 → `_show_closing_warnings` line 2734 in 4.8.2).
- **Proof:** Local red→green with the **real** `ElectrumWindow.__init__` under headless offscreen PyQt6: heavy tab/bar builders replaced by trivial widgets, stub gui_object/wallet, and `register_callbacks()` (the last step before the list was created) stubbed to deliver a window close, simulating a close during construction (`clean_up()` stubbed out — it is reached only after the buggy line). Unpatched: the exact reported traceback, surfaced via `sys.excepthook` (the same path Electrum's crash reporter uses). Patched: the mid-construction close is handled cleanly, construction completes, and the list holds the 2 registered callbacks. Repro: `~/workspace/bug-work/electrum-10969/repro_10969.py` (kept local; not a project test).
- **Fix:** create `self.closing_warning_callbacks = []` together with the other early attribute initialisations at the top of `__init__` (next to `self._cleaned_up = False`). The two `register_closing_warning_callback(...)` calls are unchanged. Patch: `fixes/electrum-closing-warning-callbacks-init.patch`.
- **Tests:** repro red→green as above; `tests.test_bitcoin` 63/63 OK as a smoke check (change is confined to `electrum/gui/qt/main_window.py`, which has no unit-test coverage upstream).
- **Submission:** PR https://github.com/spesmilo/electrum/pull/11013 — submitted 2026-10-04, OPEN/MERGEABLE at submission. Fork branch: `Kshot3000/electrum@fix/closing-warning-callbacks-init` (commit 405d96a).
