# lanl/PyBNF — free parameters differing only in case share one output file (#931)

- **Project:** lanl/PyBNF (PyBioNetFit, LANL) — https://github.com/lanl/PyBNF/issues/931
- **Sector:** web / other OSS (scientific Python application)
- **Bug:** Two free parameters whose names differ only in capitalisation (`k` and `K`) each get a per-parameter output file named after them — samplers write `Results/Histograms/<name>_final.txt`, profile likelihood writes `profile_<name>.txt`. On the case-insensitive filesystems that are the default on macOS and Windows those are the same file, so one parameter's histogram silently replaces the other's; the surviving file holds the wrong parameter's numbers. Filed 2026-09-25 by the maintainer (audit series), labeled `bug` / `silent-incorrectness`, unassigned, 0 comments, no competing PR. The issue itself suggested the fix: refuse at load.
- **Proof (red, on main eff5b16):** the issue's exact conf (edition 2, `objective = expression`, `uniform_var = k 0 10` + `uniform_var = K 50 100`, `job_type = mh`) loads with no error via the real parser + `Configuration` — variables `['k', 'K']`, histogram filenames casefold-identical. An `mh` run of the same conf completes and writes both files on this case-sensitive machine (`k_final.txt` holding k's samples ≈1.44–1.99), proving the collision is purely in the filenames.
- **Fix:** `Configuration._load_variables` now checks the built `FreeParameter` list with a new `_check_variable_name_collisions`: names grouped by `str.casefold()`; a group with >1 entry raises `PybnfError` naming both parameters and explaining the file collision + remedy. Keying on the built list covers both declaration syntaxes (legacy `*_var` keywords and edition-2 `parameter:` records, incl. mixed), the same reason `_check_variable_keyword_combination` keys on it (#603). The identical name declared twice under different kinds is refused on the same grounds (collides on every filesystem). Changelog fragment `changelog.d/931.fixed.md` included.
- **Verification (green):** issue conf refused at load; CLI prints a clean `Error:` (no traceback, no run). Control (`K`→`K2`) loads, runs the full mh fit, writes both histograms. 7 new regression tests (`TestVariableNameCaseCollisions`) pass; `test_config_class.py` failure set identical before/after (10 pre-existing, all missing `BNG2.pl` in this container); `test_parse_class` + `test_config_schema` + `test_config_unused_keys` + `test_config_golden`: 285 passed, 8 skipped. No repo example/test conf declares case-colliding names. Ruff state unchanged vs pristine (all findings pre-existing, none in the new lines).
